## Review focus

The new feature is gated by the `ENABLE_DAILY_QUOTA` Worker var (default
`false`). The behaviour on `POST /v1/scans` is byte-for-byte unchanged until
the flag is flipped to `true` on a target env. This makes the PR low-risk
to merge and review.

When the flag is off, the affected code paths are dead. The risk surface is
the new tables, the new admin endpoints, and the new admin page — all of
which are additive and isolated.

## What to verify

1. **Code paths gated by the flag.** Search for `ENABLE_DAILY_QUOTA` and
   `isQuotaEnabled`. The new branch in `apps/workers/src/routes/scans.ts`
   must be unreachable when the flag is `"false"`.
2. **Audit surfaces.** Three new log events:
   - `scan.cached_served` (no PII, only `originalScanId`, `domainKey`, `quotaDay`)
   - `redeem.applied` (admin email + `codeHashPrefix`)
   - `redeem.code_created` (admin email + `labelLength`)
3. **Packages are not a stub.** The "Gói mở rộng" UI is intentionally a
   stub. Future payment / Stripe / per-user quota is out of scope.
4. **Quota is per-host, not per-scope.** `example.com` ≠ `www.example.com`
   (the latter strips `www.`). But `example.com` ≠ `app.example.com` (the
   latter is a subdomain, not the same quota).
5. **Failed scans count.** A scan that reaches `failed` state still occupies
   the day's quota slot. The UI banner explains this.
6. **Codes are hashed at rest.** No plaintext code is persisted; only
   `SHA-256(code)` hex. The plaintext is shown once at creation and never
   returned by any subsequent endpoint.
7. **Flag-based rollout.** Enable on staging first, smoke, then enable on
   production. Rollback = flip back to `false`.

## Rollout notes

```bash
# After merge, on staging:
pnpm exec wrangler secret put ENABLE_DAILY_QUOTA --env staging
# enter: true

# Smoke:
curl -sX POST https://staging-api/v1/scans \
  -H 'content-type: application/json' \
  -d '{"url":"https://example.com","jurisdiction":"VN","category":"online_game"}'
# First time: 202 + scanId
# Second time same day: 200 + cached:true + reportUrl

# Admin route:
curl -sX POST https://staging-api/v1/admin/redeem-codes \
  -H 'content-type: application/json' \
  -H 'cf-access-authenticated-user-email: reviewer@safelaunch.app' \
  -d '{"label":"smoke","expiresAt":"2026-12-01T00:00:00.000Z"}'
# Expected: 200 + plaintext code (shown once)

# Rollback:
pnpm exec wrangler secret put ENABLE_DAILY_QUOTA --env staging
# enter: false
```

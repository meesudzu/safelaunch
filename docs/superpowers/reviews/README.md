# reviews/

Notes from `superpowers:requesting-code-review` and `superpowers:receiving-code-review`.

## Naming

`<pr-number>.md`

## What goes here

- Reviewer prompts and what we asked for.
- Concrete feedback received.
- Decisions on what to apply vs push back on (with technical reasoning).
- Final outcome (merged / closed / revised).

## Why this lives in the repo

Review feedback is the second-most-valuable documentation we produce (after
design specs). Future agents and humans can reconstruct how decisions were made
without re-litigating them.

### 3. `31ee0fe` — fix(compliance): downgrade digital-rights font license severity to review

- **Compliance surface:** this is a scoring change in
  `apps/workers/src/services/digital-assets.ts`. Triggers
  `safelaunch-compliance`.
- **Change:** `severity: "high"` -> `severity: "review"` for both the
  `isFlagged` branch and the inaccessible branch. Rationale text softened
  from "tín hiệu rủi ro" to "tín hiệu xem xét".
- **Rubric impact:** documented in
  `docs/compliance/rubrics/vn-mvp-v2-licensing-digital-rights-strict.md`
  via a Revision log entry. `RUBRIC_VERSION` is **not** bumped — the
  existing `analysis_version` values in D1 stay valid, API consumers
  don't need to change, and historical scans remain reproducible.
- **Rationale:** web fonts are routinely embedded with permissive
  web-licenses (Google Fonts SIL OFL, Adobe Fonts ToS, self-hosted
  OFL/CC). The collector only inspects redacted URLs and bounded-response
  hashes, so a missing-evidence signal reflects detection limits, not
  absence of a license. Downgrading keeps "verify before launch" as the
  right action while avoiding an unintended `high_risk` aggregate.
- **Citation framing:** unchanged — Berne Convention + Vietnam IP Law
  via `COPYRIGHT_CITATION`.
- **Compliance checklist:** all items checked in the PR description.

### 4. `f2b0aa5` — fix(web): stop Cloudflare Speed Brain from burning single-use report tokens

- **Root cause analysis (verified):** I checked the deployed URL via
  curl. The `/cdn-cgi/speculation` endpoint serves a Cloudflare Speed
  Brain rule with `href_matches: "/*"` and conservative eagerness. This
  prefetches every same-origin link on hover/viewport, including the
  report URL. The prefetch runs the Next.js server component, which
  calls `/v1/reports/by-token/{token}`, which burns the token
  (`token_hash` -> NULL) before the user actually clicks. The cached
  prefetch response makes the click look like it works, while any
  direct open of the same URL returns 404 REPORT_NOT_FOUND.
- **Fix:** `data-cf-no-prefetch` on the report `<a>` element. This is
  Cloudflare's documented opt-out for Speed Brain.
- **Comments:** long inline comment in scan-progress.tsx explains the
  root cause + fix so future engineers don't remove the "mysterious"
  attribute.
- **Tests:** new regression test asserts the attribute is present on
  the rendered `<a>`.
- **Limitation acknowledged:** the user's already-burned URL cannot be
  recovered. They need to re-scan after this ships.

# specs/

Design documents produced by `superpowers:brainstorming`.

## Naming

`YYYY-MM-DD-<topic>-design.md`

## Lifecycle

1. `brainstorming` writes a draft here.
2. User reviews, requests edits, approves.
3. `writing-plans` consumes the approved spec and writes a plan to `../plans/`.
4. Once the plan is shipped, the spec stays for historical reference (do not delete).

## How to read these as a future agent

Each spec encodes:
- The problem statement and constraints.
- The chosen approach + rationale.
- Out-of-scope items.
- Open questions.

If you are picking up an old spec, treat it as a starting point for a fresh
brainstorm, not as a contract. The world may have moved.

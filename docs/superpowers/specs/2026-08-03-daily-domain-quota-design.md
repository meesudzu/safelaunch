# Daily Domain Quota + Anonymous Redeem-Code Bypass

## 1. Background

The MVP is anonymous — every visitor can `POST /v1/scans` for free. The product team now wants to:

1. **Cap** each domain to **one fresh scan per UTC day** so the same site is not re-scanned repeatedly within 24 hours.
2. **Serve the previous result** (instead of refusing) when the user re-submits the same domain within the same UTC day.
3. **Offer a "bypass" path** for users who need a fresh scan today — but the planned paid package is **not yet released**, so the only working bypass is an **admin-issued redeem code**.

The MVP is anonymous: there is no Clerk user, no payment, no Stripe integration. The MVP uses Cloudflare Access for admin auth only. This design deliberately mirrors that — packages and redeem codes are code-based, anonymous, and guest-friendly.

## 2. Goals (in scope)

- `G1` A domain (`hostname` of the public URL) can start **at most one fresh scan per UTC day**.
- `G2` When the cap is hit, the API returns the latest **completed** scan for that domain for the same UTC day, without re-running the workflow.
- `G3` Admins can issue a redeem code that, when supplied on a subsequent scan request, **unlocks unlimited fresh scans for that domain for the current UTC day**.
- `G4` The "Gói mở rộng / Extension package" UI is a **stub** that clearly states the package is being built and that the only working bypass today is via an admin-issued redeem code.
- `G5` Zero new PII: only hashed fingerprints of the code, the host, and admin actor are persisted. No raw URL, no IP, no email beyond the `cf-access-authenticated-user-email` already used by the admin router.
- `G6` Multi-jurisdiction by default: the quota is keyed on host only; jurisdiction / category do not affect it.

## 3. Non-goals (out of scope)

- `N1` No payment integration, no Stripe, no Clerk account, no email capture. The "package" remains a stub.
- `N2` No per-user quota. There is no "user" in the MVP. The cap is global per host per UTC day.
- `N3` No retroactive re-validation of old reports. Cached responses reuse the existing scan row verbatim.
- `N4` No retroactive AI regeneration of the report. We never re-run the Workflow for a cached response.
- `N5` No support for any timezone other than UTC. `docs/remaining.md` flags timezone choices as a future Tier-2 item.
- `N6` No analytics on quota usage. We only emit structured log events (see §11).

## 4. Definitions

- `DomainKey` — the **registrable host** of the submitted URL, lowercased and stripped of any leading `www.`. Example: `https://www.Example.com/` → `example.com`. Lives in `packages/compliance-core/src/domain-key.ts` (new file, pure function, unit-tested).
- `QuotaDay` — a UTC calendar date, format `YYYY-MM-DD`, derived from `created_at` and stored as the canonical bucket key.
- `FreshScan` — a `scans` row whose `state ∈ {completed, partial, failed}` AND whose `created_at` falls in the current `QuotaDay`.
- `CachedResponse` — a 200 response that resolves a `POST /v1/scans` to the latest FreshScan for the same DomainKey + QuotaDay, **without** creating a new `scans` row.
- `RedeemCode` — an opaque, human-friendly code (e.g. `SL-A2K9-7X4P`) generated by an admin. Stored as `(id, code_hash, label, expires_at, created_at, created_by)`. The plaintext is shown to the admin **once** at creation time and never persisted.
- `RedeemGrant` — a one-time application of a `RedeemCode` to a `(DomainKey, QuotaDay)` pair. Recorded for audit and to prevent code reuse against the same slot.

## 5. Data model

### 5.1 New tables (D1, written via `packages/db/migrations/0002_daily_quota.sql`)

```sql
CREATE TABLE redeem_codes (
  id TEXT PRIMARY KEY,
  code_hash TEXT NOT NULL UNIQUE,
  label TEXT NOT NULL,
  created_by TEXT NOT NULL,
  created_at TEXT NOT NULL,
  expires_at TEXT NOT NULL,
  revoked_at TEXT
);

CREATE TABLE redeem_grants (
  id TEXT PRIMARY KEY,
  code_id TEXT NOT NULL REFERENCES redeem_codes(id),
  domain_key TEXT NOT NULL,
  quota_day TEXT NOT NULL,
  granted_at TEXT NOT NULL,
  UNIQUE(code_id, domain_key, quota_day)
);

CREATE INDEX idx_redeem_grants_lookup ON redeem_grants(domain_key, quota_day);
CREATE INDEX idx_redeem_codes_active ON redeem_codes(expires_at) WHERE revoked_at IS NULL;
```

### 5.2 No changes to existing tables

We deliberately **do not** add a `domain_key` column to `scans`. The `url` column already exists; `domain_key` is computed at lookup time using the same `packages/compliance-core/src/domain-key.ts` helper. This keeps the migration reversible and avoids a second backfill.

### 5.3 What gets persisted where

| Datum                       | Where                                        | Form                  |
| --------------------------- | -------------------------------------------- | --------------------- |
| Plaintext redeem code       | nowhere (shown once to admin)                | —                     |
| `code_hash`                 | `redeem_codes.code_hash`                     | SHA-256 hex           |
| Admin email                 | `redeem_codes.created_by`                    | header value already trusted by Access |
| Domain input                | `redeem_grants.domain_key`                   | normalized host only |
| Grant day                   | `redeem_grants.quota_day`                   | `YYYY-MM-DD` UTC      |
| Original scan URL           | `scans.url` (unchanged)                      | full URL              |
| Audit log                   | structured `console.log` (no PII)            | JSON, see §11         |

## 6. API contract

### 6.1 `POST /v1/scans` (extended)

Request body is unchanged. **New optional field**:

```json
{
  "url": "https://example.com",
  "jurisdiction": "VN",
  "category": "online_game",
  "redeemCode": "SL-A2K9-7X4P"
}
```

Response variants:

| HTTP | code                          | When                                                                                     |
| ---- | ----------------------------- | ---------------------------------------------------------------------------------------- |
| 202  | (no `code`)                   | Fresh scan accepted; existing behavior.                                                  |
| 200  | `SCAN_USED_CACHED`            | Quota hit, no redeem code (or invalid). Returns the cached payload directly (see 6.3).   |
| 400  | `INVALID_REDEEM_CODE`         | `redeemCode` present but malformed (wrong shape).                                        |
| 401  | `REDEEM_CODE_EXPIRED`         | `redeemCode` present but the code has expired or been revoked.                           |
| 409  | `REDEEM_CODE_ALREADY_USED`    | `redeemCode` already granted for this domain + day.                                      |
| 5xx  | (unchanged)                   | Server errors.                                                                           |

The cached response is **synchronous 200** because no workflow is triggered.

### 6.2 `GET /v1/scans/:id` (unchanged)

No new fields. The progress page keeps polling until terminal state.

### 6.3 New `ScanCachedResponse` shape

```ts
interface ScanCachedResponse {
  scanId: string;                            // ORIGINAL scan id
  state: "completed" | "partial" | "failed"; // see §8.4: failed scans also count
  status?: "high_risk" | "needs_review" | "no_significant_risk"; // absent when state="failed"
  coverage: { fetched: string[]; failed: string[]; skipped: string[] };
  createdAt: string;
  expiresAt: string;
  reportUrl: string | null;                 // null when state="failed"
  cached: true;                             // marker
  quotaDay: string;                         // "YYYY-MM-DD"
  domainKey: string;                        // normalized host
  message: string;                          // i18n key, e.g. "scan.cached.used" or "scan.cached.failed"
}
```

### 6.4 Admin endpoints (new)

| Method | Path                                     | Purpose                                                  |
| ------ | ---------------------------------------- | -------------------------------------------------------- |
| POST   | `/v1/admin/redeem-codes`                 | Create a redeem code (returns the plaintext once).       |
| GET    | `/v1/admin/redeem-codes`                 | List redeem codes (paginated, filter by active/expired). |
| DELETE | `/v1/admin/redeem-codes/:id`             | Soft-revoke a code (`revoked_at = now`).                 |
| GET    | `/v1/admin/redeem-codes/:id/grants`      | List grants for a code (audit).                          |

All inherit Cloudflare Access. The created-by actor is the `cf-access-authenticated-user-email` header (same as `admin.ts`).

### 6.5 `POST /v1/admin/redeem-codes` body

```json
{
  "label": "Pilot user — Vinh",
  "expiresAt": "2026-09-01T00:00:00.000Z"
}
```

Response:

```json
{
  "id": "rc_abc123",
  "code": "SL-A2K9-7X4P",    // PLAINTEXT — shown once, never returned again
  "label": "Pilot user — Vinh",
  "expiresAt": "2026-09-01T00:00:00.000Z",
  "createdAt": "2026-08-03T10:00:00.000Z",
  "createdBy": "reviewer@safelaunch.app"
}
```

`GET /v1/admin/redeem-codes` and `GET /v1/admin/redeem-codes/:id/grants` must **not** include the plaintext or `code_hash`. They expose `code_hash_prefix` (first 8 chars) for UX.

## 8. Workflow / sequence

### 8.1 User submits a fresh scan (quota available)

```
Browser → Web → Worker:
  normalize host
  day = UTC today
  no prior scan today → create scan row, enqueue workflow
  202 + scanId
```

### 8.2 User submits a duplicate (cap hit, no code)

```
Browser → Web → Worker:
  normalize host
  find latest FRESH scan today → exists
  load report row → build reportUrl
  200 cached (synchronous)
```

### 8.3 User submits a duplicate with a valid redeem code

```
Browser → Web → Worker:
  hash(code)
  find code row → valid (not expired/revoked)
  INSERT grant (UNIQUE check) → success
  create new scan row → enqueue workflow
  202 + scanId
```

If the `(code_id, domain_key, quota_day)` UNIQUE collides, return 409 `REDEEM_CODE_ALREADY_USED`. The user's previously granted scan on that day continues to work.

### 8.4 Failed scans and the quota

Failed scans (`state = "failed"`) **do** count toward the quota slot once they terminate. Rationale: a failed scan still burned LLM/worker time. The cached lookup accepts any terminal state. When the cached payload is a failed scan, `ScanCachedResponse.reportUrl` is null and `status` is omitted; the UI banner switches to "scan.cached.failed" (Vietnamese: "Quét trước đó thất bại lúc HH:MM UTC. Để quét lại, cần redeem code.").

## 9. Security & privacy

### 9.1 No new PII

- We never persist the plaintext redeem code. We persist only `SHA-256(code)` hex.
- `created_by` is the Cloudflare Access email header, which the existing admin router already trusts.

### 9.2 Rate limiting

`POST /v1/admin/redeem-codes` inherits the existing Cloudflare Access gate. No rate-limit DO is wired because the existing `/v1/admin/legal/*` does not need one.

### 9.3 Token-shape hardening

- Codes are 12 chars from `[A-Z0-9]` minus ambiguous `0/O/1/I/L`, formatted `SL-XXXX-XXXX` (8 chars after prefix).
- `SL-` prefix is a sentry: future accidental collisions with other systems are easy to grep.
- Plaintext is shown exactly once at creation. There is no "reveal" endpoint.

### 9.4 Code reuse model

A redeem code is **unlimited uses** across different domains/days, but **at most once per `(code, domain, day)`** tuple. Enforced by the `UNIQUE(code_id, domain_key, quota_day)` constraint on `redeem_grants`.

- Same code, same domain, same day → second apply returns 409.
- Same code, different domain, same day → both succeed.
- Same code, same domain, different day → succeeds.
- Same code, expired → 401.
- Same code, revoked → 401.

### 9.5 Audit trail

Two new log events (privacy-first):

- `scan.cached_served` — keys: `originalScanId`, `domainKey`, `quotaDay`. No URL, no IP, no email.
- `redeem.applied` — keys: `codeId`, `codeHashPrefix`, `domainKey`, `quotaDay`, `actor`.

## 10. Edge cases

| Case | Behavior |
| ---- | -------- |
| User submits URL with `www.` prefix | `domain_key` strips `www.`. Same quota. |
| User submits URL with trailing slash | Dropped — `(url).host` is already canonical. |
| User submits URL with query string | Ignored — host is the same. |
| User submits a domain with no successful scan today but a failed scan | `SCAN_USED_CACHED` with the failed scan's status. UI banner explained. |
| Two users submit the same domain 1 second apart | Second request gets `SCAN_USED_CACHED` to the first user's fresh scan. |
| User starts a scan near midnight UTC, scan completes after midnight | The scan's `created_at` (queuing time) determines the quota day. |
| User submits a malformed redeem code | 400 `INVALID_REDEEM_CODE`. |
| Admin revokes a code mid-day | Code continues to count for grants already issued; new applies return 401. |
| User clears cookies / uses a different IP | Quota is per host, not per IP. New IP still gets cached. |
| Worker restarts mid-scan | The original scan row already exists in D1; the quota slot is already taken. |
| `redeemCode` field is empty string | Treated as omitted. |

## 13. Rollout

1. Migration `0002_daily_quota.sql` is **additive**: existing tables are untouched. Existing scan rows remain queryable.
2. The new code path is **disabled by default** via a feature flag: `ENABLE_DAILY_QUOTA`. When the flag is `false`, the existing `POST /v1/scans` behavior is byte-for-byte unchanged. The flag is read from environment in the Worker.
3. The flag is off for staging initially. We turn it on in production only after a manual smoke run on staging.
4. No destructive deletes. No data migration. No backfill.

## 14. Open assumptions to confirm with user

These were encoded as defaults but the user is invited to override any:

1. Quota scope = host (registrable domain). `example.com` ≡ `www.example.com`.
2. Day boundary = UTC.
3. Failed scans count against the quota.
4. Packages are a UI stub; the only working bypass is redeem codes.
5. Redeem code = unlimited checks for a `(domain, day)` pair.
6. Plaintext code is shown once at creation; admins copy it out.
7. No per-user quota, no auth (anonymous).
8. New admin page lives under `/admin/redeem-codes` (same Access gate).
9. New `apps/web/src/messages/{vi,en}.json` `quota` and `package` blocks.
10. Feature flag `ENABLE_DAILY_QUOTA` gates the new code path.
